# CLAUDE.md — Loveopoly

Board game web untuk pasangan & teman (Bahasa Indonesia). JS biasa (ES modules, tanpa framework UI) dibangun **Vite** dari `index.html` + `src/main.js` ke `dist/` (JS, CSS & font bernama hash → di-cache lama), dihosting di Firebase Hosting. Antarmodul selalu `import/export`; `window.Love*` (`LoveEngine`, `LoveUI`, `LoveNet`, ...) hanya kait uji & debug yang dipasang `src/main.js`, jangan dipakai di kode aplikasi.

## Perintah

- Build: `npm run build` (Vite → `dist/`; wajib sebelum uji browser: uji melayani `dist/` lewat `test/helpers/serve.js`, modul ES tidak bisa dibuka lewat `file://`)
- Pratinjau: `npm run dev` (Vite, http://localhost:5173, muat ulang otomatis) atau `npm run preview` (hasil build)
- Kualitas: `npm run check` = `lint` (ESLint, `eslint.config.js`) + `format:check` (Prettier, `.prettierrc.json`) + `typecheck` (TypeScript `checkJs` untuk `src/engine`, tipe JSDoc di `src/engine/types.js`, `jsconfig.json`). Perbaiki dengan `npm run lint:fix` / `npm run format`. CI GitHub Actions (`.github/workflows/ci.yml`) menjalankan check + build + semua uji (termasuk emulator) di tiap push ke `main` & pull request; jaga tetap hijau.
- Uji: `npm test`, atau per bagian `npm run test:sim | test:progress | test:flows | test:online | test:ui | test:a11y | test:migrate | test:rules | test:backend` (dua terakhir menjalankan Firebase Emulator, butuh Java 11+). `test:a11y` = axe-core WCAG 2.1 AA di layar & dialog utama, terang/gelap, desktop/HP; tambah tampilan baru ke sana.
- Deploy: `npm run deploy -- --project prod`. Coba dulu di kanal pratinjau: `npm run deploy:preview -- --project prod` (alamat sementara 7 hari).
- Sebelum menyatakan selesai: build + uji yang relevan harus lulus dan **tanpa error konsol**. Perubahan tampilan: cek juga screenshot di `test/out/`, minimal ukuran 1366×768, 820×1180, 390×844, 844×390, tema terang & gelap.

## Aturan produk

- Semua teks UI Bahasa Indonesia, santai & hangat. Angka pakai format `id-ID` (`fmt()`).
- Seni orisinal (SVG di `src/assets/art.js`). Jangan meniru aset, karakter, atau branding Get Rich / game lain.
- Ikon: `public/icon.svg` satu-satunya sumber; `npm run icons` (`tools/icons.mjs`) membuat `icon-32.png`, `apple-touch-icon.png` (180, tanpa sudut membulat), `icon-192.png`, `icon-512.png`, `icon-maskable-512.png` (isi 78% di zona aman). Ubah SVG → jalankan ulang.
- PWA: `public/manifest.webmanifest` + `src/service-worker.js` (disusun plugin di `vite.config.js` jadi `dist/sw.js`: daftar precache = berkas hasil build + ikon, versi = hash daftar & `index.html`, cache lama dibuang saat aktif). Halaman jaringan dulu (update langsung sampai), `/assets/*` cache dulu, origin lain (Firebase) tidak disentuh. Didaftarkan `registerServiceWorker()` (`src/ui/install.js`) hanya di build produksi dan tidak saat `navigator.webdriver` (uji), kecuali URL `?uji-sw` (`test/pwa.js`). Tombol "Pasang Aplikasi" di menu beranda muncul bila `installMode()` = `prompt` (event `beforeinstallprompt`) atau `ios` (petunjuk Tambah ke Layar Utama).
- Dependensi: jangan menambah dependensi runtime atau CDN baru (alat build/uji di `devDependencies` boleh). Pustaka luar hanya SDK Firebase compat 10.14.1 (gstatic) yang dimuat malas oleh `src/net/backend.js` saat menu online dibuka (uji memakai `node_modules/firebase`), dan gtag.js Google Analytics (`src/analytics.js`, lihat di bawah).
- Latar halaman ringan (gradasi CSS `.page-sky`, tanpa kanvas/WebGL) dan **diam di luar suasana**. Saat Kabar Merpi / Musim Puncak, dua lapisan `.sky-a`/`.sky-b` di dalam `.page-sky` boleh bergerak, tapi hanya `transform`/`opacity` (berulang mulus: lapisan lebih besar satu ubin, digeser satu ubin), dan mati saat reduced motion. **Jangan pakai `backdrop-filter`** (blur kaca) di header, scrim, atau overlay, dan jangan beri `filter: blur` pada lapisan yang bergerak (blur lembut taruh di dalam SVG polanya). Di atas latar & papan yang terus bergerak, blur dihitung ulang tiap frame, dan di sebagian GPU (layar besar, Chrome/Safari) header pernah berkedip hitam/hilang. Pakai latar hampir pekat atau scrim yang sedikit lebih gelap. Tengah papan (kamera 3D & ponsel) memakai Merpi besar `#mascot` (SVG + CSS 3D, tanpa WebGL): alas globe & bayangan rebah di papan, Merpi berdiri tegak. Reaksi lewat `mascotAct()` (kelas `act-*`), `mascotEmote()`, `mascotLook(petak)`; mood ikut `merpiSay()`, tertidur setelah 30 detik diam. Globe hidup ringan (benua/awan/cincin berputar pelan, Merpi bergoyang `msIdle`). Suasana Kabar Merpi & Musim Puncak: `renderAmbience(S)` (dipanggil dari `renderStage`) memasang `body[data-amb]` + `body.amb-peak` → warna tengah papan (`.ctr-amb`) + suasana seluruh ruangan di latar halaman (`.page-sky::before` gradien warna di bawah pola, `.sky-a`/`.sky-b` pola SVG bergerak ringan: hujan turun & awan bergeser, matahari berputar, % naik, pesawat melintas, koin jatuh, hati melayang, senja berdenyut) + properti kecil dekat Merpi di `.ms-fx`/`.ms-orbit`/`.ms-peak` (payung & tetesan, label %, koin, hati, pesawat mengitari globe, cincin emas). Efek dekat Merpi tidak boleh naik melewati deretan kartu kota (cuaca besar taruh di latar ruangan); kosong = default. Hilang/berganti selalu memudar: `renderAmbience` mempertahankan `data-amb` lama + `body.amb-leave` selama `AMB_FADE` (1,2 dtk), baru melepas/mengganti; semua bagian suasana tampil lewat `opacity` dengan `:not(.amb-leave)` (jangan pakai animasi `opacity` di lapisan suasana, pakai filter/stroke-opacity supaya pudar tidak tertimpa). `show()` saat keluar game memanggil `renderAmbience(null)`. Merpi kecil di panel disembunyikan di mode ini; `#bubble` (aria-live) dipindah `placeStage()` ke `#boardVP` dan diposisikan `trackBubble()` di atas kepala Merpi besar.
- Hemat daya (`src/ui/core/power.js` + `src/styles/power.css`): hiasan yang berulang terus membuat HP menggambar ulang ±60×/dtk walau permainan diam, sehingga HP lemah cepat panas. `body.calm` menjeda semua hiasan berulang (kecuali latar Kabar Merpi/Musim Puncak `.sky-fx`: penanda acara, hanya transform/filter di GPU, tetap bergerak; di Hemat baterai 3× lebih pelan lewat `--sky-slow` pada durasi di `ambience.css`) setelah 12 dtk tanpa kejadian (bangun lewat `wakeCalm()`: sentuhan/tombol, `renderStage`, `mascotWake`, pindah layar), dan selamanya di mode Hemat baterai (`body.lowp`, Pengaturan → `prefs.power` `auto`/`save`/`full`; Otomatis = Hemat Data, Android `deviceMemory` ≤ 4, atau `probeFps()` < 40 fps di sesi ini: hasil ukur **tidak disimpan** (Mode Daya Rendah iPhone / penghemat baterai Android sementara membatasi 30 fps), kabar sekali per perangkat `prefs.powerTold`; `prefs.powerSlow` versi lama dibuang `initPower`). Hiasan berulang (`animation … infinite`) baru **wajib** masuk daftar `power.css`; animasi permainan sekali jalan di elemen yang sama dikecualikan lewat `:not()`. Hiasan hanya menganimasikan `transform`/`opacity` (bukan `box-shadow`, `background-position`), karena itu dikerjakan GPU tanpa cat ulang. Animasi SVG SMIL (pesawat peta `.cd-map`) tidak ikut CSS: dijeda lewat `pauseAnimations()` (`syncSmil()`), juga saat petanya tersembunyi (3D/HP); dulu pesawat tak terlihat itu sendirian membuat main thread sibuk ±39% saat diam. Diuji `test/flows.js`: diam 12 dtk → tidak ada animasi berjalan.
- Warna lewat token CSS di `:root` (`src/styles/tokens.css`) + dua blok tema gelap (media query & `[data-theme="dark"]`). Jangan menaruh warna literal yang hanya terbaca di satu tema. Teks berwarna di atas latar `*-soft` pakai token `*-ink` (`--danger-ink`, `--mint-ink`, `--gold-ink`, `--sky-ink`), bukan `*-d` (`*-d` untuk bayangan/ikon; di tema gelap terlalu redup untuk teks).
- Aksesibilitas: axe WCAG 2.1 AA 0 pelanggaran (`npm run test:a11y`); hormati `prefers-reduced-motion` (`reduceMotion()`); tombol punya label. Nama aksesibel harus memuat teks yang terlihat (pakai `.sr-only` sebagai pelengkap, bukan `aria-label` yang berbeda); area yang bisa digulir diberi `tabindex="0"`.
- Privasi: dokumen online diberi `expireAt` (+7 hari, `src/net/backend.js` `encode`); aturan membatasi `expireAt` ≤ 8 hari. **TTL belum aktif**: kebijakan TTL Firestore butuh paket Blaze (billing). Setelah Blaze aktif, isi `firestore.indexes.json` dengan `"fieldOverrides": [{ "collectionGroup": "<rooms|locks|lobby|intents>", "fieldPath": "expireAt", "ttl": true, "indexes": [] }]` (empat entri), deploy, lalu kembalikan janji "terhapus otomatis 7 hari" di `openPrivacy()` (`src/ui/modals/menu.js`) & catatan kamera Foto Bukti (`src/ui/modals/challenge.js`). Tanpa TTL pun room dibersihkan: host yang keluar dari permainan yang **sudah selesai** (`exitToHome` → `Net.closeRoom()`) menghapus room + kunci host; tamu tetap di layar menang (snapshot "room tidak ada" saat `App.S.over` = toast halus, bukan ditendang); tamu menghapus `lobby/<uid>` miliknya begitu status room bukan `lobby` (`Net.lobbyDoc`). Room yang ditinggal sebelum selesai tetap tersimpan sampai TTL aktif. Teks Privasi tidak boleh menjanjikan hal yang belum berlaku.

## Arsitektur

- Struktur `src/`: `main.js` (titik masuk: impor gaya & modul, kait `window.Love*`, lalu `start()`), `engine/` (`data.js`, `engine.js` = barrel objek `E` dari `rules/*.js`, `ai.js`, `types.js`), `assets/` (`icons.js`, `art.js`, `audio.js`, `fonts/`), `ui/` (`ns.js`, `core.js` + `core/*.js`, `modals.js` + `modals/*.js`, `screens.js` + `screens/*.js`, `guide.js`), `net/` (`firebase-config.js`, `backend.js`, `net.js`), `styles/` (`index.css` mengimpor bagian-bagian; urutan impor = urutan kaskade, jangan diacak). `public/` disalin apa adanya ke `dist/`.
- `core.js`, `modals.js`, `screens.js`, `engine.js` adalah barrel: mengumpulkan API bagian-bagiannya (modul lain mengimpor dari barrel). Panggilan "ke atas" (inti → dialog/layar) lewat registri `UI` (`src/ui/ns.js`, diisi `Object.assign(UI, …)` di barrel) supaya tidak ada impor melingkar. Kode tingkat atas modul jangan membaca `const`/`let` modul lain yang ikut siklus impor (TDZ): state & konstanta bersama di bagian dasar (`ui/core/base.js`, `engine/rules/base.js`) yang tidak mengimpor bagian lain. Impor ES hanya-baca: ubah variabel milik modul lain lewat fungsi setter (mis. `setStageEl`). Handler aksi engine didaftarkan ke registri `H` (`rules/base.js`) oleh `rules/actions.js` & `rules/challenge-actions.js` (diimpor `rules/dispatch.js`).
- Jahitan uji: `window.LoveBackend` (backend aktif dibaca saat dipakai lewat `backend()`; mock uji memasang/menggantinya) & `window.LOVE_FIREBASE` (config; emulator di uji backend).
- `src/engine/` murni & deterministik (ESLint melarang global browser di sana): `E.dispatch(state, action)` mengembalikan `{ ok, state | error }`. UI dan online hanya memanggil ini; aturan baru masuk ke `src/engine/rules/` + `test/sim.js`.
- `SIDES` di `src/engine/data.js` (petak 1–7, 9–15, 17–23, 25–31) dipakai syarat menang "jalur": papan harus tetap 7 petak per sisi (jangan ganti bentuk papan).
- Header hanya berisi satu tombol `#hMenu` (beranda & game). `UI.openMenu()` membuka menu beranda (Panduan, Suara, Pengaturan, Paspor, Privasi) bila belum ada game, atau menu permainan (+ Riwayat, Asetku, Jeda, Keluar, Akhiri, Menyerah). Suara diubah lewat `UI.toggleSound()`; jangan menambah tombol header baru, taruh di menu.
- Menutup dialog/overlay selalu beranimasi, cermin animasi bukanya: pakai `UI.leave(el, ms, deep)` (id dilepas, `inert` + `aria-hidden`, kelas `.leaving` di `src/styles/modal.css`, dihapus setelah animasi; langsung hilang saat reduced motion), jangan `el.remove()` langsung. `closeModal()` menaruh `#modalRoot` baru yang kosong dan menjadikan yang lama bayangan (memudar di desktop, turun sebagai sheet di HP); `showModal()` langsung membuang sisa bayangan. Logika tidak menunggu animasi.
- Tata letak (`computeLayout()` di `src/ui/core/layout.js`): `wide` (desktop/tablet mendatar, panel aksi di kolom kanan saat 3D), `mid` (tablet tegak, dok bawah), `compact` (HP tegak), `land` (HP mendatar). Jarak aman (aplikasi terpasang di iPhone: ±59 px atas, ±34 px bawah): `<html>` diberi padding `env(safe-area-inset-*)` (gaya di `index.html`), jadi tinggi `body` / `body.in-game` / `.game` selalu dikurangi jarak aman, kalau tidak dokumen lebih tinggi dari layar dan kartu pemain tergulir ke bawah header yang menempel. Layar game tidak pernah tergulir (`keepGameTop()` di `src/ui/screens/base.js` mengembalikan ke atas, kecuali saat mengetik); diuji `test/flows.js` lewat CDP `Emulation.setSafeAreaInsetsOverride`.

## Papan 3D (`src/ui/core/camera.js` + `src/styles/board.css` & `board-cards.css`)

- Kamera: `translate → rotateX(tilt) → scale3d(s) → translate(-fokus)` + `perspective` pada `#boardVP`. `fit3d()` mencari skala terbesar agar seluruh papan + kartu berdiri muat (ruang `HEAD`/`FOOT`). Tilt 30° (area tegak) / 38° (area datar), sama untuk semua mode.
- Mode: "Semua" (bawaan, diam) dan "Dekat" (ikuti pion, `pref3d = 'near'`). Di HP, `auto3d()` = "Sorot langkah": mendekat saat pion jalan / ada keputusan di petak, lalu kembali ke seluruh papan.
- Kartu pop-up `.t-pop` adalah billboard: `rotate: x calc(var(--tilt) * -1)`, `transform-origin` di bawah. `--px` / `--pb` / `--pw` = titik kaki & lebar kartu per sisi petak.
- **Isi elemen 3D harus tetap di dalam kotaknya.** Anak `position: absolute` yang menjulur keluar kotak elemen ber-transform 3D bisa terpotong kompositor Chrome (pernah terjadi pada mahkota & titik level). Perbesar kotak/padding, jangan mengandalkan overflow.
- Pion berdiri di depan kartu (baris atas/bawah & sudut) atau di sisi dalam petak (kolom kiri/kanan). Kartu tidak boleh menutupi pusat petak di belakangnya, karena ketukan harus mengenai petak yang benar.
- Mengangkat badge "ke atas layar" tanpa `transform` (supaya animasi tidak bentrok): `translate: x calc(L * -1 * cos(var(--tilt))) calc(L * sin(var(--tilt)))`.
- Efek datar di bidang papan (riak, debu) diberi `translate: 0 0 3px` agar tidak tertutup muka petak.
- **Jangan membuat lapisan 3D yang berjarak tipis** (beberapa px `translateZ`) di dalam elemen berdiri, misalnya ketebalan/punggung kartu. Safari/WebKit tidak bisa mengurutkan bidang sedekat itu dan jatuh ke urutan DOM: muka kartu tertutup lapisannya sendiri, label koin tertutup kartu tetangga, lalu berkedip saat animasi (dilaporkan di iPhone). Kartu `.t-pop`/`.tp-card` sengaja `transform-style: flat` (satu bidang). Begitu juga Merpi besar: `.ms-stand`/`.ms-look` datar (badan, efek koin/hujan/hati, emote, zz satu bidang), dan `mascotLook()` menoleh lewat geser + miring 2D, bukan `rotateY` (sisi belakangnya tenggelam ke globe). Cek perubahan papan 3D juga di WebKit (`playwright` `webkit`, ukuran HP); catatan: WebKit headless tanpa GPU tidak menjalankan ruang 3D sama sekali (semua bidang rata, urutan DOM), jadi pakai untuk mendeteksi ketergantungan pada urutan 3D, bukan untuk menilai kemiringan kamera.
- Balikan kartu di dialog (Kartu Cinta `.love-card`) **2D**: `scale` x 1 → 0 → 1 dengan punggung (`.lc-back`, bertumpuk di atas muka) hilang tepat di titik 0 (`lcBack*` sinkron dengan `lcFlip`/`lcLand`). Jangan kembali ke `rotateY` + `backface-visibility`: Safari iOS meratakan 3D di dalam dialog ber-`overflow` & sudut membulat, putaran tidak terlihat.
- Animasi Buku Panduan yang berpindah tempat memakai `cqw`/`cqh` (`.sc` = size container), bukan px tetap, supaya di HP tidak kelewat keluar adegan.

## Aturan peluncuran (keseimbangan & kejutan)

- Keadilan kursi: semua pemain sama persis (START, modal sama, tanpa bonus/diskon). Giliran pertama diundi: `E.create({ ..., first: 'random' })` dipakai setup, "Main lagi", dan room online (`S.start`); bawaan `first: 0` untuk uji. `nextTurn` menghitung ronde baru saat giliran kembali ke `S.start`, jadi semua dapat jumlah giliran sama. Game baru dengan undian: `drawReveal()` (`src/ui/screens/game.js`, overlay `#drawOv`, kelas berawalan `dp-`/`dw-` supaya tidak bentrok dengan `.win` layar menang) mengungkap `S.turn.p` → lalu tur (perangkat yang belum pernah) → main. Undian (dan tur tanpa undian) tampil saat kartu papan sudah berdiri (`afterBoardIntro()`: `INTRO_MS` 1,15 dtk atau saat kelas `.enter` di `#board` dilepas); ketukan di `#game` / Enter / Spasi / Esc melewati sisa intro (ketukan ditelan, tidak membuka petak). Penangkap ketukan hanya dipasang bila ada undian atau tur yang menunggu. "Lewati" di undian cukup sekali (hasil 0,65 dtk lalu tutup); hasil menutup sendiri 1,6 dtk. Target: bisa melempar ±5 dtk tanpa menyentuh, ±1,7 dtk bila terburu-buru (diuji `test/flows.js`). `App.revealing` dipasang di awal `enterGame` dan merahasiakan siapa yang jalan duluan sampai undian selesai: baris giliran "Mengundi giliran…", tanpa sorotan kartu pemain/pion, tanpa tombol aksi, entri log "Undian giliran:" disembunyikan (`visibleLog`). `App.revealing` & `App.tourPending` menahan bot di perangkat host; tur teman baru tidak menahan permainan orang lain.
- Cara menang instan: Trio Warna (`triple`, wajib ada grup 3 kota → `tripleOk`), Raja Jalur (`line`), Kolektor Wisata (`spots`). Jangan memakai kata "Monopoli/Monopoly" (merek dagang) di teks.
- Ketemuan! (`meetUp` di `land`): berhenti di petak pemain lain → semua yang bertemu dapat `meetCash` & `meetLove`, sekali per giliran, event `meet`.
- Kabar Merpi (`S.news`, `drawNews` di `startRound` tiap `E.newsGap(S)` ronde (menurut durasi `RULES.newsGap`: Singkat 4, Normal 5, Panjang 6, Bebas 5; tidak muncul saat Musim Puncak), berlaku `newsLasts` ronde; matikan dengan `settings.news = false`): rain/holiday (tol satu jalur ×0,5/×1,5), sale (diskon 20%), promo (World Tour gratis, `E.travelFee(S)`), bonus (gaji +100), love (Love berlipat). `E.newsInfo(S)` untuk UI.
- Musim Puncak (`E.peakOn(S)`): `peakRounds` ronde terakhir permainan berbatas ronde, tol ×`peakMult`, event `peak`.
- Reaksi emoji (`UI.EMOTES`, `showEmote`, `sendEmote`): bukan aksi engine. Online: intent `EMOTE` diproses host di `processIntent` → field `fx` dokumen room, tidak mengubah `seq`.
- Paspor Cinta (`src/ui/screens/passport.js`, kunci `loveopoly.v1.profile` yang juga dipakai profil online): muncul sekali saat pertama buka (bisa "Nanti saja"), mengisi Pemain 1 di setup, `recordPassport()` di `showWin` mencatat main/menang/cap kota. Pesan romantis layar kemenangan ada di paspor (`p.msg`, satu-satunya tempat mengisinya): dibawa ke pemain (`player.msg`) saat game dibuat (lokal: pemain bernama sama dengan pemegang paspor; online: lewat kursi room), layar menang menampilkan pesan pemenang atau pemain lain yang menulis; `settings.winMessage` hanya untuk save lama. Uji mengisi `{ skipped: true }` di init script supaya paspor tidak menghalangi.

## Progres Paspor (Jam Terbang, Api Cinta, lencana)

- Logika murni di `src/ui/progress.js` (tanpa DOM & tanpa impor, diuji `npm run test:progress` / `test/progress.js`, juga di zona waktu lain); UI di `src/ui/screens/passport.js` (kartu beranda, halaman paspor, `notePlay`, `kangenNote`), `win.js` (panel Jam Terbang + layar perayaan), `home.js` (Merpi kangen), gaya `src/styles/progress.css`.
- Semua progres hanya di paspor perangkat (`loveopoly.v1.profile`: `xp`, `wk` {last, n, best, umb}, `life` {ch, lm, lt, sm}, `seen`), **tidak pernah** memengaruhi permainan (keadilan kursi). `passport()` menormalkan & hanya mengembalikan field yang dikenal, dan `savePassport` menyimpan hasil itu: field baru wajib ditambahkan ke `passport()`. Penulis lain menggabungkan ke profil terkini, jangan menimpa (lihat `bindProfile` di `online.js`).
- Api Cinta = rekor **minggu** beruntun (minggu lokal Senin–Minggu, `weekNo` lewat tanggal lokal → `Date.UTC`, kebal DST). Satu minggu tercatat saat game mencapai ronde 3 (`notePlay` dari `renderStage` lewat registri UI, kabar toast) atau selesai (`recordPassport`). Payung Rindu menutup minggu bolong otomatis (dapat 1 tiap 4 minggu, maks 2). Jam mundur tidak mengubah apa pun.
- Jam Terbang: XP game selesai (`XP`: selesai 20, menang 30, tantangan 5, cap kota baru 5, minggu Api Cinta 10), level `levelXp(L) = 30·(L−1)·L` dengan gelar `RANKS`. `recordPassport` sekali per game (kunci `p.last`), mengembalikan ringkasan untuk layar menang. Lencana seumur hidup bertingkat Perunggu/Perak/Emas (`BADGES`; tingkat Emas Kolektor Cap = jumlah kota, dicek test).
- Layar perayaan (`#celebOv`, `role=status`, bukan dialog) hanya saat naik level / lencana naik tingkat: tutup sendiri ±2,4 dtk, ketukan/Enter/Spasi/Esc ditelan supaya tidak mengenai tombol layar menang, tidak muncul di atas Kartu Kenangan/dialog. Merpi kangen: sekali per sesi bila ≥ 5 hari tidak membuka (pengunjung baru tidak). Diuji `test/flows.js` & `test/a11y.js`.

## Tantangan (wajib terbukti)

- Tidak ada hasil yang dinilai sendiri: `CH_RESOLVE` hanya `skip` & `choice` (dilema). Hasil lewat `CH_ANSWER` yang dinilai engine.
- `CH_TYPES[type].verify`: `auto` (trivia, price, recall, math, scramble, emoji: soal dibuat engine dari seed di `it.pz`, jawaban dinilai `gradeAuto`, batas waktu dari `ms`), `duel` (secret, bluff, charades: lawan ikut main), `judge` (dare, photo: lawan manusia mengesahkan), `message` (syarat dicek `messageChecks`, lalu disahkan lawan bila ada), `choice`.
- Item `CHALLENGE`: `p` pemilik, `who` yang sedang beraksi (`actor()` memakainya), `judges` semua lawan manusia urut giliran (`judgesFor`, bot tidak pernah menilai) diputar per pemilik lewat `S.chRot` (`it.rot`, `assignJudges`), `judge` = `judges[0]` (penilai utama / target Tebak Isi Hati), `phase`, `isle` (Rindu Challenge, syarat lebih ringan dari varian `*Isle` di `CH_TYPES`). Tipe yang butuh penilai diganti tipe auto bila tidak ada lawan manusia. Pemilik boleh `skip` kapan saja (penilai pergi).
- 3–4 pemain (`judges.length > 1`; berdua tetap satu penilai, persis seperti dulu): dare/photo/message → `judgeVote` (semua penilai memilih bergantian lewat `who`, `pz.votes`; mayoritas, seri = sah; semua pemilih dapat `judgeReward`, `chFinish(..., judgeShare)` menerima array). Bluff → `pz.picks` per penebak, pemilik menang bila `fooled >= caught`, hadiah hanya penebak benar. Charades → tebak serentak: `chActors(S)` = penebak yang masih punya kesempatan (`pz.triesBy`), `dispatch` menerima `CH_ANSWER` dari mereka meski bukan `actor()`; tebakan benar pertama menang sendiri, `giveUp` per penebak, `timeout` mengakhiri semua. UI: satu layar "Serahkan ke …" per penilai (gerbang `'guess'` untuk tebak bersama, pilihan penebak `data-gsr`); online tiap HP menjawab sendiri (`syncModal` memilih aktor dari `E.chActors`).
- Bukti: `S.proofs` (log hasil) & `S.photos` (maks 4 foto JPEG ≤ 22 KB, dipajang `#proofPin` di papan, galeri `openProofs()`). `E.migrate(S)` menyiapkan ulang tantangan save lama.
- Satu HP: layar "Serahkan ke …" (`#bGate`) tiap kali `who` berpindah orang. Uji: `test/sim.js` (aturan), `test/flows.js` (UI), `test/online.js` (duel lintas perangkat), `test/online3.js` (3 perangkat: tebak serentak & voting).

## Online (`src/net/net.js` + `src/net/backend.js`)

- Host-authoritative di atas Firestore: `rooms/<KODE>` (hanya pemegang lease menulis), `rooms/<KODE>/locks/host` (lease `{uid, holder, exp}`, maks 60 detik), `lobby/<uid>` & `inbox/<uid>/intents/<id>` (hanya pemilik uid). Host memvalidasi setiap intent dengan engine, menolak `baseSeq` basi, mencatat ack.
- `src/net/backend.js` = adapter `LoveBackend.use('db' | 'user' | 'room')` dengan API yang dipakai `net.js`. Dokumen disimpan `{ __j: JSON, ...kunci indeks }` (Firestore menolak array bersarang); kunci indeks `hostUid status room uid exp holder` dipakai `where` & aturan. Presence di RTDB `presence/<KODE>/<uid>`. Login anonim.
- Aturan di `firestore.rules` & `database.rules.json`; setiap perubahan aturan wajib diikuti `npm run test:rules`.
- Tamu menerima state lewat `onRoomSnap`: `commit` hanya bila `seq` lebih besar; game baru ("Main lagi", `seq` mulai 0) dikenali dari `seed` yang berbeda → `enterGame`. Jangan menghapus pemeriksaan `seed` itu.
- `test/online.js` & `test/online3.js` memakai mock `window.LoveBackend` berbasis localStorage (`test/helpers/mock-backend.js`; `backend.js` tidak menimpa backend yang sudah terpasang).
